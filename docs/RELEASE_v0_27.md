# CONGLOMERATE Ver.0.27 — 次世代部品経済基盤

**開発試作版 / 2026-11-17**

基準：Ver.0.26（Git Blob `9fa201c8f303e71440c25c44e750febc80bf8614`）。正式基本設計Ver.3.0・SPEC-001〜094と次世代確定NEXT-001〜012を維持。

## 新機能（基盤のみ）

1. `State.partEconomy` に内部スキーマ `schemaVersion:1`、`nextSerial:1` と部品仕様／ライセンス／共同開発契約／売買契約／注文／輸送／取引イベント／AI設備投資の**空台帳**を追加。
2. `Firm.partOperations` に製品開発案件・方針・実行月、部品ロット、部品製造計画、承認車種の**空補助台帳**を追加。
3. 既存車種には `componentMode:'legacy'` を補完。旧車種の製造方式と既存 `factoryOps.mode`（旧3部品方式）に変更なし。
4. `ensureV27` は決定的・冪等・無乱数・無資金移動。旧セーブは既存チェックサムを検証した後に新台帳を補完。読み込みに失敗した場合、現在のゲームと保存データは変更しない。
5. `validatePartEconomyV27` は未対応のデータ版、未実装の実取引、不正なID・会社参照・数量・台帳型・車種モードを拒否。既存 `check(s)` に接続し、月次処理で不整合を防ぐ。
6. `initFirm` と `newGame` が新しい空台帳を用意する。月次中に誕生した法人も対象。保存・設定に「基盤準備済み／取引は未実装」と表示。

## Ver.0.27では実行しないもの

**部品設計費・ライセンス料・部品売買・AIライン投資・新BOM量産は一切実行しません。** これらはVer.0.28〜0.29で設計・実装・検証する対象です。現行の800研究技術、M&A、株主、工場、物流、販売、連結会計、AI設定と月次工程は変更していません。

## 保存互換・注意事項

- 外部JSON封筒 `format:'CONGLOMERATE', version:1`、従来のチェックサムとIndexedDB保存世代方式を継承。ゲーム内に `partEconomy.schemaVersion:1` を追加。
- **旧セーブ（Ver.0.26）→Ver.0.27**：移行テスト済み。**Ver.0.27→Ver.0.26への逆移行**：保証対象外。
- 旧セーブJSONの元データは公開リポジトリに配置していません。テストは新規作成した合成ゲームのJSONで行いました。
- IndexedDBをすべてのOS・ブラウザで終了・再起動して検証したものではありません。ゲーム更新前に必ずJSONバックアップを作成してください。
- G0〜G5は基盤の合格基準であり、将来のVer.0.28〜0.29のBOM生産・企業間取引の品質保証ではありません。
