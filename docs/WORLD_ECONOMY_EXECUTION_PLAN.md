# CONGLOMERATE — 世界経済拡張の実装・検証・統合計画

## 正式目標

確定仕様001〜174のすべてを、動作する単一HTMLゲームで実装・検証する。40経済市場（うち英国＋アイルランド、スペイン＋ポルトガル、ベネルクス、バルカンを統合市場として扱う）、1900年開始、150品目（資源30・素材45・設備30・消費財30・サービス15）、800研究、歴史変遷、国内国際物流、都市地図、銀行、企業AI、M&A、保存、オフライン・長期耐久までが対象。

この文書は実装タスクの進行表であり、新しい仕様を勝手に決定する資料ではない。原本は \`CONGLOMERATE_確定仕様台帳_174項目.md\` と設計v0.1/v1.0を優先する。

## 安全な開発運用

- 実装ブランチ: \`codex/world-economy-full\`。ユーザー指定の仕様台帳・進捗表・設計資料を参照する。
- \`main\` は既存のプレイ可能版として保持。必須テストと174項目の適合監査が合格するまで上書きしない。
- 既存の研究ID、法人・資産・帳簿のID・所有権・参照・月次ロールバックを保全する。
- 技術や地理史実の初期データを仮置きする場合、\`DATA_CANDIDATE\` / \`PROVISIONAL\` を消さず、実装済みと判定しない。
- 旧セーブ移行は仕様168により必須ではない。一方、新形式の保存、前世代復旧、月次再現性は必須。
- 未合格で停止する場合は修正結果と失敗したテストを作業ブランチへ記録し、完成宣言をしない。

## 優先順序

1. 直近コミットとPRのCIの失敗原因を特定し、**新規不具合**は修正する。
2. Phase 2の残り商品と「生産→売買→在庫→原価」を段階実装。製造可能な商品が1種類増えただけでPhase 2完了としない。
3. Phase 3/4の共通受注・検収・決済が固まった後に、国際物流と資源・財務の全面統合を行う。
4. 支配権判定の70%への切替は権限・連結・株主名簿・M&Aを同時検査できるPhase 7で実施する。単独の表示閾値変更は禁止。
5. 既存の120か月成功は新174仕様の全面合格を意味しない。大規模長期試験・復旧・性能計測を別に行う。

## 運転・回帰に関する注意

- 現行ゲームは約1MBの単一 \`index.html\`、800研究技術、37画面、BOM、仕訳、M&Aの試作コードを持つ。
- 直前の世界基盤には40市場/155都市、5旧市場＋暫定ノルウェー接続、銅線1品目の試作がある。
- Phase 2-Aで35レシピ＋銅線試作1件、Phase 2-Bで有限鉱床台帳（初期空）とサービス15件の非物理分類を追加。Phase 2-Cで暫定レシピ11件を追加し計46レシピ＋銅線1件。Phase 2-Dでさらに暫定レシピ15件を追加し計61レシピ＋銅線1件、残り88候補。有限鉱床の月次稼働と同一拠点現物検収、燃料消費を伴うローカル発電を試作。Phase 2-Eで物理銅線送電・使用kWhに応じた燃料簿価の製品原価配賦・当月鉱床採掘から現物検収までを接続し、合計71製造レシピ＋銅線1件、残り78候補へ拡張。Phase 2-Fで設備減価償却・廃止と現物機関車・石炭・輸送前払/検収の国内B2B試作を追加し、計80暫定製造レシピ＋銅線1件、残り69候補へ拡張。正式な史実路線・資産の会社間移転と検収の全面対応は未完成。電力必須製品は広域送配電網未実装のため初期停止し、実燃料発電または同一拠点で有限送電したkWh、あるいは明示的TEST_FIXTUREの有限月間枠でのみ製造する。売買・実鉱床・電力網を含む150品目すべての稼働と174項目の監査は未完成。
- 以前の一部CIは旧セーブ移行など、仕様変更で期待値の更新が必要。失敗の内容を記録し、旧テストを理由なく無効化しない。

## Phase 2-H・2-I・2-J

- 2-Hは買い手の手動発注、売り手の承諾・拒否、翌月の先着・部分受注、共通出荷への接続を対象とする。
- 2-Iは実生産計画の材料不足を基準とする独立AIの発注を対象とする。未成立注文や輸送中数量を二重計上せず、プレイヤーは手動発注を維持する。
- 2-Jは新規の発注由来出荷の仕訳照合と、グループ内の前払・返金の連結CF消去を対象とする。専用Playwright、37画面、会計・保存、世界経済120か月を検証する。
- 次の2-Kは連結在庫の原価来歴、裏付けのある通常プレイ向け調達源、適合する受入設備への荷種追加から着手する。1,200か月の合否と最新HEADは着手時に照合する。

## Phase 2-K

- 引継ぎHEADの1,200か月4ケースを確認してから、国内取得原価の履歴を実装する。単体原価を維持し、国内グループ内の売上と残存在庫・設備に含まれる未実現利益を連結時に消去する。
- 当該原価方式の合格条件は部分消費、再販、グループ外への売却と買戻、単体・連結差額、保存復元と旧形式の回帰。確認後、通常画面からの有限の地域現物購入を接続し、購入した貨物・燃料で鉄道と道路の出荷・検収を確認する。

## Phase 2-Lの受入状況

- 物理は資源30品目の有限現物仕入、104製造レシピと銅線試作1品目を個別に検証する。
- 非物理は現物在庫を作らず、実際の契約・貨物・会計・人員・設備に結び付いた履行のみを対象とする。外部主体への支払いは利用側の確認であり、提供側の完了判定には別の証拠が必要。
- サービス12品目に試験で確認できる履行経路がある。未接続の医療、不動産賃貸、宿泊観光と利用側に限る経路の提供側を検証し、150品目のゲートが合格してからPhase 3へ進む。

## Phase 2-M — 医療S08の実施証拠（2026-11-23）

- 国内東京の試作医療サービスとして、1950年以後の稼働拠点・有償取得した現物医療機器E27・研究解禁を確認して、提供施設を資産化する。条件劣化・月次償却・閉鎖と固定資産処理を既存台帳へ接続する。年代・料金・診療能力係数、医療資格の扱いは **PROVISIONAL**。
- 実在する営業・管理職員の人数から専任の医療業務枠を割り当て、複数施設に同一人数を重複配属しない。資格・職種別給与・独立した医療従事者育成と全国の提供網は未接続であり、現段階の割当人数を正式な資格保持者とみなさない。
- 依頼、部分実施、取消、月次実施枠を別台帳で管理する。未実施の依頼に売上も請求も発生せず、完了した診療件数だけの利用側費用・提供側売上、連結上の内部取引消去・キャッシュフロー相殺を行う。
- `tests/test_world_phase2m_medical.py` で現物・枠・未実施ゼロ・部分実施・未実施取消・帳簿/連結・改竄拒否・保存・償却/閉鎖を確認する。**CI合格およびPhase 2完了は個別の結果確定後のみ判定。**
- **Phase 2全体は未合格。** S12不動産賃貸・S14宿泊観光、旅客・外部借入・技能教育・工事の提供側を完了するまでPhase 3には進まない。

## Phase 3：市場・B2B（ユーザー指定の正式工程）

Phase番号を増やさない。このPhaseの内部要件は①国別消費需要と固定都市配分・地域価格、②既存B2Bの先着順・部分受注と市場需給の連動、③在庫・検収・会計・保存の確認。①を実装したが②③は未完了。Phase 2の未完了は監査事項として保持し、Phase 3の着手を止めない。実装が不十分な間はPhase 3完成とは宣言しない。

- Phase 3の国内実取引接続：消費財需要を独立AI企業の原料調達判断へ接続し、実在庫の原価と国内注文状況を使う地域価格を適用する。推計だけでは商品販売・仕訳を生成しない。実物流・会計・保存は既存処理を使用し、専用CIで検証する。
