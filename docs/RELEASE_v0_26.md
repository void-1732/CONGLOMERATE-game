# CONGLOMERATE Ver.0.26 — 工場人員・稼働率・調達と画面改修

**2026-11-17 / 開発試作版**

## 起動方法

`index.html` をChrome / Edgeで開くか、Python 3がある環境で同じフォルダーから `python -m http.server 8765` を実行し、`http://127.0.0.1:8765/index.html` にアクセスしてください。オフラインで動作します。

## 主な修正

1. **工場別の人員配置:** 製造部門の従業員を工場へ自動配分。工場を選び「設備・人員設定」で固定人数にもできます。すべて会社の既存従業員から配分され、工場を増やしても雇用人数は増えません。固定配置の合計は製造部門の人数を超えられません。旧セーブは自動配置として読み込みます。
2. **人員による生産能力制限:** 部品工場（詳細3モジュール方式と従来の共通部品方式）の製造数量を人員で制限。支援工場の能力補助は、実際に人員と生産計画がある工場に限ります。
3. **原材料調達の修正:** 契約在庫目標に完成車だけでなく部品工場の原材料所要量を含めます。総合完成車工場の内製時に必要な鋼材・ゴムも計算。安全在庫「最大」は需要に対する**在庫目標を2倍**にするもので、即時に在庫を補充するものではありません。
4. **調達の診断:** 7資材ごとに、需要・目標在庫・現在庫・輸送中・前月入荷・前月使用・前月発注・供給不足を表示。「仕入先能力不足」「輸送期間中」「入荷しても同月に消費」を区別して判断できます。
5. **緊急スポット調達:** 鋼材・ゴム・アルミニウム・銅・ガラス・化学原料を市場の残余供給上限内、1種類につき毎月1回・最大30単位、通常より45%高い参考単価で即時購入できます。現金と材料を実際に仕訳し、二重実行を防止します。
6. **工場UIの圧縮:** 工場一覧と詳細を左右に置き、詳細を「稼働診断」「生産・物流」「設備・人員設定」の3タブに分割。各ペイン内をスクロールし、画面全体の縦移動を低減。専門部品工場3種類の製造計画と配送をまとめて初期設定するボタンも追加。

## 工場が稼働率0%のとき

- **生産・工場の製造方式**が「詳細方式」か「従来方式」か確認してください。
- **部品工場:** 月間製造量が0の場合は製造されません。「部品工場を一括セットアップ」を使うと、詳細方式・月次部品製造・自動配送を初期化できます。原材料・人数・現金と配送先も確認してください。
- **完成車工場:** 対象車種の生産計画、材料、従業員、組立部品の到着状況を確認してください。総合完成車工場は原材料があれば3モジュールを内製できます。
- **原材料:** 仕入契約を保存するだけでは在庫は増えません。次回月末の調達・輸送を待つか、上限付き緊急調達を使います。月末在庫が0でも、前月入荷と消費に同数が記録されていれば調達自体は進んでいます。

## 互換性・検証

- 研究800技術・車両設計・製品・市場分析・M&A・新株発行・自動経営管理センター・連結会計は維持。
- JSON保存形式 `VERSION=1` を維持。Ver.0.25の実JSONセーブをインポートして36か月継続、会計・連結CF検算合格。
- 専門部品工場3種の配置・製造・輸送を含む60か月連続処理で検算合格。100拠点・390pxモバイル幅で検索・選択・画面タブを検証。緊急調達の会計計上・1か月1回制限も確認。
- 継続プレイの前に**旧版からJSONバックアップを書き出してください**。実ブラウザを閉じて再起動した後のIndexedDB永続性は全OS・全ブラウザで保証する試験を完了していません。
- 給与・設備・輸入価格・供給能力はゲーム用の試作係数です。緊急スポット調達も現実の市場取引を再現したものではありません。
