開発試作 v0.4 / 2026年11月16日
============================================================

【はじめに】
本版はv0.3から引き継いだ開発試作版です。正式な会計基準への適合や
基本設計書の全項目の実装が完了した製品ではありません。
正式設計はVer.3.0 / SPEC-001〜094を維持します。設計質問91〜93は未回答、
SPEC-095以降は未確定であり、本版の仮定は正式仕様の決定を意味しません。

【起動方法】
1. ZIPを任意のフォルダーへ展開。
2. Windowsでは CONGLOMERATE_start_local_v0_4.bat を実行。
   Python未導入の場合はPythonを導入するかHTMLを直接ブラウザで開きます。
3. ブラウザで次のURLへアクセス：
   http://127.0.0.1:8765/Corporate_Simulation_Prototype_v0_4.html
4. 創業条件を設定し、会社・子会社を経営します。
5. 左側の「連結財務三表」で連結BS・PL・CFと取得情報、為替明細を確認。

注意：同じブラウザでも file:// と http://127.0.0.1:8765/ は別の保存領域です。
保存データが見つからない場合は、従来の起動方式に戻って旧版でJSONを出力し、
新バージョンの「保存・設定」からJSONを読み込んでください。

【v0.4の主な変更】
1. 取得日・取得時点の帳簿を保存する取得スナップショットを追加。
   取得先の財務・現金・収益・費用・通貨・取得時の換算レートを記録。
   取得価格と取得時簿価に基づく仮の取得差額を照合可能にしました。
2. 連結キャッシュフローの対象期間を明確化。
   外部現金取引の発生月と取引時レートを記録し、内部貸付・利息決済・
   内部商品の現金移転、子会社設立時の払込金を連結CFから区別します。
   支配獲得時に引き継いだ現金を投資CFへ別途反映。
3. 月末連結CFを履歴として保存。
   月次確定後に次の月の買収・会社間取引を入力しても、前月CFと
   現在残高を誤って比較しないようにしました。
4. 外貨換算の追加検証。
   取引時の変動スポットレート、期末の変動スポットレート、取得時レートを
   区別します。外貨換算差をCF本体から分け、現金の増減を照合します。
   円／円の為替レートが変動していた不具合を修正（JPYは1固定）。
5. 保存画面に「IndexedDB実機診断（既存セーブ非変更）」ボタンを追加。
   本人のブラウザで、独立キーへの書込→読出し照合→DB接続を閉じて再開
   →再読出し照合→診断データ削除を確認します。
   診断は「active」の保存世代参照や既存セーブ内容を変更しません。
   ※診断に成功してもブラウザデータ削除・端末故障からの復元は保証しません。
6. 同一のIndexedDB名（CONGLOMERATE_LOCAL_V02）、保存版番号(version=1)と
   JSON保存形式を維持し、v0.2／v0.3セーブ互換性を重視しました。

【会計上の制限：重要】
・BSとPLの全科目はv0.3から継承した固定基準レート換算の試算値です。
  v0.4で追加した変動レートの換算・CF照合は現金についてのブリッジです。
  連結BS・PLの全項目を正式な外貨換算ルールで換算する処理ではありません。
・取得差額の計算は「取得時帳簿価額に対する仮評価」です。取得時公正価値への
  配分、のれん・割安購入差額の正式認識、期中取得に関する厳密な日割り等は
  未確定であり、公式の財務諸表には該当しません。
・旧版の取得台帳・取引時為替レートが残っていない過去データは、
  復元できる範囲で計算します。CF照合に「要確認」と表示されることがあります。
・非支配株主持分、複雑な循環持合い、連結CF・外貨換算差額を含む
  全会計処理への正式会計基準適合は完成していません。
・歴史的な国境・通貨制度と史実為替データは未完成です。

【テスト実施状況】
実施済（この実行環境でのChromium、モック保存層を使用）：
・JavaScript構文検証。
・子会社・孫会社、60%買収、非支配株主持分、内部貸付、未実現利益の画面／会計検証。
・外国企業の取得初月の連結CF、取得現金、期間境界、変動為替差の照合。
・外国子会社向け貸付を含む6か月のCF照合。
・外国子会社設立後のCF照合（通貨換算端数の許容差を明示）。
・月次120回・10年間の連続試験：月次・会計・連結検算とCF照合、JSON往復一致。
・v0.3形式のJSONデータの読込と月次継続。
・IndexedDB書込み・読戻しを模擬した保存世代のポインタ切替失敗と
  最新世代の破損時に前回正常世代への復旧を確認。
・保存診断操作のロジックを模擬保存層で実行、既存セーブ参照が不変であることを確認。

未完了・別環境での検証が必要：
・この自動検証環境のChromiumでは file://、http://localhost、127.0.0.1 等の
  ページ遷移が管理上ブロックされるため、実際のIndexedDBを使った起動・
  書込・ブラウザ再起動後のロード試験は実施できていません。
・ユーザーの実ブラウザでは「保存・設定」→「IndexedDB実機診断」を使い、
  その後、手動セーブ→ブラウザ再起動→保存復元を確認してください。
・100年以上の長期安定性、巨大持株会社、複数ブラウザなどの正式受入試験。

【安全な保存方法】
・旧版から引き継ぐ前に「JSONバックアップ」を作成して安全な場所へ保存。
・3つの自動保存領域を、最新・前回確定・書込候補に使用。
・手動セーブは3つのスロット。保険としてJSONの外部コピーを保管。
・保存診断ボタンは既存の手動・自動保存データを変更しないよう設計。
・IndexedDBだけでは端末故障・ブラウザデータ削除を防止できません。
